# Action candidate resources

Store machine-readable action manifests in this directory. The current test uses
one global `action_catalog.json` containing every trusted candidate exposed to the
init planner; actions are not grouped or labeled by task.

Each entry contains the stable action name, a concise description, and a trusted
``perception`` contract.  That contract is not generated by the VLM.  It declares
whether the in-task VLM must return current-front-image 2D point hints, whether a
color hint is required, fixed by the trusted catalog, or unused, the point's exact
semantic meaning, and the trusted ``grounding_backend``. The VLM must never return
or choose the backend, pose, depth, metric position, size, orientation, quaternion,
transform, point cloud, mask, or bounding-box values.

The three VLM-point backends are:

- ``grasp_grounding``: OpenCV masks the complete object and F2G estimates the
  declared pose and optional size;
- ``side_grasp_grounding``: OpenCV masks only the VLM-selected black or white peg
  half and F2G estimates that half's pose;
- ``location_grounding``: aligned depth directly back-projects the VLM point to a
  world position; OpenCV and F2G are not called.

``scene_grounding`` remains the separate whole-scene path for
``scene_target_set`` actions.

An action that remains intentionally deferred may also contain the paired fields
``implementation_status: incomplete`` and ``implementation_note``.  Keeping such
an entry in the catalog documents the intended action boundary without claiming
that its semantic argument sources are execution-ready.

The supported perception modes are:

- ``none``: the action has no target geometry and the VLM returns no point;
- ``vlm_points``: the VLM returns exactly one 2D point for each declared role;
- ``scene_target_set``: the perception backend extracts the declared ordered target
  set from the whole scene, so the VLM returns no per-target coordinates.

For ``color_hint: fixed``, the entry also contains ``fixed_color``. The VLM still
returns ``color_hint: null`` and predicts only the role's 2D point; the grounding
pipeline applies the trusted catalog color when OpenCV constructs the mask.
For ``color_hint: required``, an optional ``allowed_colors`` list restricts the
VLM to trusted visible labels. Peg endpoint actions currently use only ``black``
and ``white`` so OpenCV segments one physical half before F2G estimates its center.

Parameterized actions may declare ``semantic_arguments`` with
``source: subgoal_text_tokens``. Runtime resolution searches the rendered subgoal
for independent word tokens; it does not compare the complete subgoal sentence
against an enumerated phrase. For example, any unambiguous sentence containing
``left`` maps to the left-side insertion value even if the surrounding wording
changes.

The catalog covers the action semantics exposed by the Oracle Plus adapters and the
RoboMME Oracle Planner options for all 16 tasks. Parameterized Oracle variants,
such as insertion side, grid direction, target side, and circling direction, remain
arguments of one stable action instead of becoming duplicate task-labeled actions.
Do not put executable Python, task labels, or generated task plans in this file.

The init planner receives this file as `action_candidates_path` and must infer the
relevant subset from the task description and action semantics.
